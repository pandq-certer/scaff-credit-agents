# 办公机联调验证步骤（原子智能体 ↔ SYS-01 服务器）

> 适用：办公 Mac（Apple Silicon）跑 3 个原子智能体，SYS-01（OCR 8101 / 解析 8102）部署在内网服务器 `172.20.80.12`。
> 网络模型：办公机登录 VPN → SSH 隧道 → agent 以 `localhost:8101/8102` 访问服务器。

## 0. 前提检查

| 项 | 要求 |
|---|---|
| VPN | 已登录，能访问 `172.20.80.12`（`nc -z -v 172.20.80.12 22`） |
| JDK | 21（`java -version`） |
| Maven | 3.9+（`mvn -v`） |
| 仓库 | `scaff-credit-agents`，`git pull` 到最新 `main` |
| SSH | 建议先配免密：`ssh-copy-id root@172.20.80.12`（需管理员同意） |

```bash
git clone https://github.com/pandq-certer/scaff-credit-agents.git
cd scaff-credit-agents
git pull origin main
git log --oneline -2     # 至少包含 a4514f0（扫描 PDF 接入 8102）
```

## 1. 建立 SSH 隧道（单独终端，保持不关）

```bash
ssh -N -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -o ExitOnForwardFailure=yes \
  -L 8101:127.0.0.1:8101 -L 8102:127.0.0.1:8102 root@172.20.80.12
```

- `ExitOnForwardFailure=yes`：本地端口被占用时立即报错，不会静默失败
- 长时间联调建议 `brew install autossh`，把上面命令改成 `autossh -M 0 ...`

## 2. 本机先验隧道

```bash
curl -sS http://localhost:8101/healthz
curl -sS http://localhost:8102/healthz
```

期望：

```json
{"status":"ok","model":"PP-OCRv5_server"}
{"status":"ok","service":"doc-parse","ocr":"http://ocr:8101","db":"ok"}
```

解析服务的 `db` 字段单独暴露库状态（2026-11-19 新增）：`db:"down"` 时服务仍返回 200，但解析结果可能未落库，需通知服务端排查 PG。

两条都通再继续；不通先查 VPN 与隧道。

## 3. 构建并启动三个 agent

```bash
cd scaff-credit-agents
mvn -pl ocr-agent,doc-parse-agent,image-agent -am -DskipTests package

java -jar ocr-agent/target/ocr-agent-1.0.0-SNAPSHOT.jar --server.port=18101 > /tmp/ocr-agent.log 2>&1 &
java -jar doc-parse-agent/target/doc-parse-agent-1.0.0-SNAPSHOT.jar --server.port=18143 > /tmp/docparse-agent.log 2>&1 &
java -jar image-agent/target/image-agent-1.0.0-SNAPSHOT.jar --server.port=18155 > /tmp/image-agent.log 2>&1 &
```

说明：

- agent 默认 `bai.*.sys01.base-url = http://localhost:8101`、`parse-base-url = http://localhost:8102`，与隧道一致，**无需改配置**
- 如需显式指定，可覆盖：
  `BAI_OCR_SYS01_URL` / `BAI_DOCPARSE_SYS01_URL` / `BAI_DOCPARSE_SYS01_PARSE_URL` / `BAI_IMAGE_SYS01_URL`
- 三个 controller 都校验 `X-Request-Id` 请求头，缺失返回 400 `PARAM_MISSING`

## 4. 三条链路冒烟

```bash
IMG=<本地任意 jpg/png，建议用一张申请表扫描图>
RID="office-$(date +%s)"

# OCR
curl -sS -m 300 -H "X-Request-Id: $RID-ocr" \
  -F "image=@$IMG" http://localhost:18101/api/bai/ocr/recognize

# 文档解析
curl -sS -m 900 -H "X-Request-Id: $RID-docparse" \
  -F "file=@$IMG" http://localhost:18143/api/bai/docparse/parse

# 图像质量
curl -sS -m 120 -H "X-Request-Id: $RID-image" \
  -F "file=@$IMG" http://localhost:18155/api/bai/image/quality
```

## 5. 通过标准

| 链路 | 期望 |
|---|---|
| OCR | `code="0"`，`blocks` 非空，首块约「个人经营性贷款申请表」，`qualityScore` 接近 0.89 |
| 文档解析 | `code="0"`，`readingOrder` 正文来自 OCR（如「申请人姓名：张伟」），扫描 PDF 走 8102 |
| 图像质量 | `code="0"`，`quality.score≈0.893`，`usable=true`，`suggestion=ACCEPT` |

## 6. 排错

| 现象 | 原因 / 处理 |
|---|---|
| `Connection refused` (8101/8102) | 隧道断了或未建立；重开第 1 步 |
| `400 PARAM_MISSING ... X-Request-Id` | 漏了请求头 |
| `40001/40002` | 文件类型或解析失败；`message` 已带真实异常，服务器侧 `docker logs --tail 80 sys01-parse` |
| healthz 返回 `db:"down"` | PG 不通：解析可能成功但未落库，联系服务端处理；错误码不会因此变成 500 |
| `40003` | 图像质量不合格（模糊/过暗），换图重试 |
| `40004` | 加密 PDF，需人工处理 |
| 首条 OCR 60s+ | 服务器首次加载模型，正常；二次约 14s/2 页 |
| agent 启动报端口占用 | 用 `lsof -iTCP:18101 -sTCP:LISTEN` 查并换端口 |

服务器侧排查（需运维授权）：

```bash
docker compose -f /opt/credit-platform/sys-01-docproc/docker-compose.server.yml ps
docker logs --tail 80 sys01-parse
docker logs --tail 80 sys01-ocr
```

## 7. 证据留存

把三条 curl 的完整输出保存到文件，提交给交付方：

```bash
{ echo "== OCR =="; curl -sS -m 300 -H "X-Request-Id: $RID-ocr" -F "image=@$IMG" \
    http://localhost:18101/api/bai/ocr/recognize; echo; \
  echo "== DOCPARSE =="; curl -sS -m 900 -H "X-Request-Id: $RID-docparse" -F "file=@$IMG" \
    http://localhost:18143/api/bai/docparse/parse; echo; \
  echo "== IMAGE =="; curl -sS -m 120 -H "X-Request-Id: $RID-image" -F "file=@$IMG" \
    http://localhost:18155/api/bai/image/quality; echo; } | tee office-verify-$(date +%Y%m%d-%H%M).log
```

## 8. Nacos（可选，直连不需要）

当前三条链路的地址是写死的显式 URL，**不依赖注册中心**。服务器上的 8848 是共用 Nacos 实例，未经允许不要注册 agent；确需验证注册发现时，先取得授权，并让 agent 使用独立 namespace：

```bash
export NACOS_ADDR=172.20.80.12:8848
export NACOS_NAMESPACE=<单独申请的 namespace>
```
